# 0003 阶段一改为每个位置都做选择，先量出瓶颈再写 kernel

状态：提议（2026-11-22），待确认。依据 #28 的把关实验，回答 ADR 0002 留下的两个问题：训练 kernel 要不要写、范围多大，以及推理时 prefill 是否改为展开。相关 issue：#16、#25、#27、#28。

## 背景

ADR 0002 事先定了门槛：在 8K 上，「阶段一每个位置都做选择」的模型（B）满足任一条，就写训练用的选择 kernel。一是推理时后缀每个位置都展开，后缀 KL 比现有做法（A，阶段一不做选择、只在 decode 展开）至少低 20%；二是 pass key 在上下文前半段时，准确率至少高 10 个百分点。

两个模型都是 Qwen2.5-0.5B，用同样的数据、同样的 300 步、同一个 seed，k=16。结果如下（后缀 KL 来自 16 条 8K 序列，passkey 来自 30 个样本）：

| 模型 | 推理时的选择 | 后缀 KL | passkey 前半 | passkey 后半 |
|---|---|---|---|---|
| A | 只在 decode | 0.776 | 0.20 | 0.13 |
| A | 每个位置 | 0.735 | 0.27 | 0.20 |
| B | 只在 decode | 0.414 | 0.00 | 0.07 |
| B | 每个位置 | 0.385 | 0.13 | 0.33 |
| 老师 | — | 0 | 1.00 | 0.87 |

**第一条门槛达到，第二条没有。** B 每个位置都展开时，后缀 KL 比 A 只在 decode 展开时低 50%。前半段的 passkey 反而低了 7 个百分点，但 30 个样本的标准误约为 7 个百分点，而且所有配置都离老师很远，这一项说明不了方向。

**收益来自训练，不来自推理。** 只改训练（A 换成 B，推理都只在 decode 展开），KL 降 47%。只改推理（只在 decode 换成每个位置都展开），A 降 5%，B 降 7%。也就是说，阶段一在有选择的条件下训练，模型学到的 summary 更好用；推理时 prefill 是否展开影响很小。

**代价已经可见。** 8K 时 B 每步 47.8 s，A 每步 21.6 s。现在的实现（#28）先按 decode 规则对每一行逐级选择，再把结果写成稠密的 [T, T] 可见矩阵，然后转成 flex 的 BlockMask。这个矩阵在 32K 时每个 KV 组有 10 亿个元素，128K 时放不下。#21 的 replay 也说明了同一件事：瓶颈是构造 mask，不是 attention 本身。replay 每层构造 [H, T, T] 的 BlockMask，在 128K 时占了每步一半以上的时间。

## 决定

**阶段一改为每个位置都做选择。** 这是门槛给出的结论。选择的规则与 decode 相同：逐级保留 k 个节点，选择的下标不求梯度，逐层 MSE 的老师仍是全注意力，路由 KL 保留。阶段二（OPSD）不变：rollout 已经在做选择，replay 照记录重算。

**推理时 prefill 仍只读 summary。** 展开只带来 5–7% 的 KL 下降，抵不上 prefill 也要一套选择 kernel 的代价。ADR 0001 和 0002 的这一条不变。等到 #27 要做 256K 以上的外推时，如果质量瓶颈转移到 prefill，再重新评估。

**kernel 只写实测的瓶颈，第一步是测量。** 在 0.5B 上，测 32K 和 128K 时阶段一一步里选择、构造 mask、attention 各占多少时间和显存。预计的范围有两块。

- **选择本身。** 把 decode 的 kernel A（逐级 rank-select）推广到一次处理很多行。现在的参考实现是逐行的 PyTorch 循环。
- **从选择结果直接产生块稀疏结构。** 每个 query 块和 KV 组算出要访问的 key 块列表，直接填进 BlockMask 的下标，不经过稠密矩阵。

attention 的 forward 和 backward 继续用 flex：选择的下标不求梯度，所以 backward 就是普通的块稀疏 attention，flex 已经支持。只有测量显示 flex 的块粒度（128）浪费太多时，才考虑自己写 attention kernel。

自己写完整的稀疏 attention forward 和 backward（像 RecSA 那样）没有选：它的代价最高，而现在没有证据说明 attention 是瓶颈。

**flex 的短 query backward bug 要绕开。** torch 2.8 里，flex 编译过别的形状之后，如果 query 行数 ≤ 128、BlockMask 又是编译出来的，backward 会算错（`experiments/flex_short_q_bwd.py`）。阶段一按整段序列做 backward，不受影响；但如果新的实现把行切成小块分别调用 flex，每块至少要有 256 行。

## 后果

新开一个 issue：阶段一每个位置都做选择的长上下文实现。先测量，再写批量的选择 kernel 和直接产生块下标的结构；验收标准是在 0.5B、128K 上训练得动，并且与 #28 的参考实现选出相同的节点。#22（7B-1M）的阶段一依赖它。

这次的结论只来自 0.5B、8K、300 步的一组实验。到 32K 以上，如果 B 相对 A 的优势消失，这份 ADR 需要重开。新 issue 的验收里要包括在 32K 上重做一次 A/B 对比。
