# 0002 训练时是否做选择：先用数据把关

状态：已接受（2026-11-21）。补充 ADR 0001 的两处决定：「追加的 token 只读 summary，不做展开」和「选择只靠路由 KL 训练」。相关 issue：#16、#19、#21、#27。

## 背景

这份 ADR 回答一个问题：要不要像 RecSA（Wang 等，2026，arXiv 2611.07232）那样，让阶段一和 prefill 的每个位置都在有选择的条件下训练和运行。

RecSA 和我们的做法有三处不同，下面的决定都由它们引出。第一，RecSA 训练的前向本身就是稀疏 attention：32K 训练序列里每个 query 都逐级选出 k 个候选，反向时重算选择，所以训练也需要 forward、backward 两套 kernel。我们只在 OPSD 的 rollout 里做选择，它不求梯度；replay 照记录重算，没有 top-k；阶段一完全不做选择。第二，RecSA 把没选中候选的 summary 留在 softmax 里，它们直接收到 loss 的梯度；我们的设计里它们完全不可见，只能从路由 KL 拿到梯度。第三，RecSA 让每个条目的 RoPE 位置等于它在本级候选里的序号，32K 训练外推到 2M（RULER 49.3，全注意力加 DCA 为 27.6）。

我们自己的结果也指向第一、二处：OPSD 在 8K 的 passkey 上只有 0.32，pass key 在上下文前半段时只有 4%，失败集中在压缩区深处。但两种方法从未在同一设置下比较过，RecSA 的基座、训练量和评测都与我们不同，所以这份 ADR 不直接改变 0001，而是先用便宜的实验确定差距有多大。

## 决定

**推理时仍只有 decode 做选择性展开。** 追加的 prefill 只读 summary，ADR 0001 的这一条不变。每轮追加的工具结果可能有几万 token，让每个位置都选，prefill 就必须有 RecSA 那样的 kernel；而两种做法的质量差距还没有数据。prefill 是否也要展开，由下面的把关实验回答。

**选择能力由粗粒度项和路由 KL 一起学，先在 OPSD 的 replay 里实现。** 粗粒度项打开时，没选中的候选留在 softmax 里，反向 KL 的梯度直接流到它们；路由 KL 保留作辅助 loss。replay 只对几十到几百个生成行求梯度，加入粗粒度项只是在 gather 时多带上兄弟节点，不需要新的训练 kernel。这样能单独量出端到端梯度的价值，和更贵的「阶段一也做选择」分开评估。只用路由 KL、或只用端到端梯度都没有选：前者留着没选中节点学不到 KL 信号的盲点，后者去掉了训练时就有的真实 mass 标签。

**粗粒度项打开时采用精确划分。** 选中的节点只看它的子节点，自己的 gist 不再可见；没选中的节点只看自己的 gist。压缩区里的每段内容恰好被算一次，全部展开时退化为原模型，噪声底仍为 0，mass 的账也清楚。这也定下了 handoff 里「展开后 summary 是否可见」这一待定项：粗粒度项关闭时，旧路径保持 SSA 的 SG+SR（选中节点的 gist 与展开内容同时可见）不变。SG+SR 加粗粒度项没有选，因为选中部分的 mass 会被重复计算。

**训练用的选择 kernel 先用数据把关。** 在 Qwen2.5-0.5B、4–8K 序列上，用 #19 的 PyTorch 参考实现做一次「阶段一每个位置都做选择」的实验：每个位置按 decode 的规则选择，选中块的原始 token 可见，逐层 MSE 的老师仍是全注意力，选择的下标不求梯度，路由 KL 保留。只让一部分位置做选择没有选，因为结果介于两者之间，难以解释。对照是同规模、同步数的现有做法。

**门槛事先定好：满足任一条才写训练 kernel。** 一是在 8K 上，推理时让后缀每个位置都按 decode 规则展开，后缀 KL 至少下降 20%；二是 pass key 在上下文前半段时的准确率至少提高 10 个百分点。KL 衡量整体质量，后者衡量已知的薄弱点。两条都没达到，就不写训练 kernel，ADR 0001 的做法保持不变。

**把关实验与 kernel 的工作并行。** 它只依赖 #19，与 #20 无关；结果决定 kernel 的范围要不要扩大到训练的 forward 和 backward，越早知道，#20 的接口越不容易返工。

**按候选序号定位置只用于 256K 以上。** 这个做法会改变原始 token 之间的相对位置，全部展开时学生与原模型的位置不再相同，噪声底为 0 的不变式不再成立，而它是 OPSD 信号干净的前提。256K 以内原位置已在模型的训练范围内，没有理由放弃这个不变式；256K 以上它是 #27 的首选候选。

**RecSA 作为基线，按做法逐项比较。** 端到端选择、粗粒度项、按候选序号定位置、组内 sum-exp 合并都做成我们框架里的开关，在同一模型、同一数据上逐项量出贡献。直接跑 RecSA 的代码没有选：基座、训练量和 summary 的构造方式都不同，即使它更好，也说不清是哪一项起的作用。

## 后果

ADR 0001 的结构不变，新增的工作有三项：#19 的参考实现支持精确划分的粗粒度项；#21 的 replay 在 gather 时带上兄弟节点；新开一个把关实验的 issue，依赖 #19。门槛达到时，再写一份 ADR 决定训练 kernel 的范围，以及 prefill 是否改为展开。
